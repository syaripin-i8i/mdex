# Task: Define CLI output and schema release boundaries

Align the public CLI contract documentation with the formats actually emitted by each command, without wrapping or otherwise changing existing success payloads.

## Acceptance criteria

- Separate schema-backed objects, unwrapped utility JSON, table rows, and `open` source text.
- Document that every error remains schema-backed JSON on stderr with a non-zero exit code.
- Keep the actual utility primary keys, including `node_id`, in the command table.
- Treat `contract_schema` as a stable logical identifier paired with `contract_version`.
- Pin published schema retrieval to the matching immutable release tag, without claiming that an older release contains a newly added schema.
- Distinguish CLI output schemas, the scan configuration input schema, and telemetry.

## Results

- Classified every successful command as schema-backed JSON, unwrapped utility JSON, table rows, or `open` source text without changing existing payload shapes.
- Corrected utility output keys to the emitted `node_id` forms and documented that every error remains schema-backed JSON.
- Defined `contract_schema` as a stable logical identifier paired with `contract_version`, with immutable published retrieval from the matching `v{contract_version}` tag.
- Separated output, scan configuration input, and telemetry schemas; documented `scan-artifacts` as a `scan.schema.json` variant and declared its artifact-specific fields.

## Verification

- README/schema consistency and all output-schema CLI tests pass.
- The complete test suite and schema validation pass.
