# Task: Fail closed on invalid document scan configuration

Add a JSON Schema for document scan configuration and validate every
existing configuration before `scan` or `finish --scan` builds an index.

## Acceptance criteria

- Unknown keys and invalid value types fail before DB or JSON outputs are written.
- Document lane, scan root, extension, exclusion, scoring, and synonym settings are validated.
- Missing optional configuration keeps the existing default behavior.
- Repository, task-history, and quality-fixture configurations validate successfully.
- The schema remains discoverable from an installed wheel or sdist.

## Results

- Added a Draft 2020-12 input schema with closed top-level and scoring objects for document lanes, roots, extensions, exclusions, node types, summaries, synonyms, and output paths.
- `scan`, `finish --scan`, and the quality evaluator now share the same validator and reject unknown keys, invalid types/lanes, non-standard or non-finite numbers, and oversized input before index output.
- Missing default config remains optional; CLI `--config` retains priority, while an explicitly configured runtime path is required and cannot silently fall back.
- Schema discovery supports checkout, editable/venv, wheel, sdist, and `pip --target` layouts.

## Verification

- Dedicated scan-config tests cover repository/task/memory configs, fail-closed errors, CLI override precedence, size limits, and installed layouts.
- Wheel and sdist builds pass `twine check`; isolated `pip --target` installs load the packaged schema outside the repository.
- The complete test suite and coverage gate pass.
