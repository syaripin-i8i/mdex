# Task: Adopt zero-hit disclosure for find and context

2026-07-10 の cdex Intake 評価 (cdex decisions/0003) で、エージェントが `mdex find` / `mdex context` の 0 件を「存在しない」と解釈する事故が確認された。0 件がメタデータレーンの範囲しか束縛しないことを payload で自己申告する。field 名 (`lanes_searched` / `lanes_inactive` / `caveat` / `remediation`) は cdex `zero_hits` (cdex `51c9ffa`) と共通語彙。適用判断と実装は mdex レーン (Fable-side)、共通プロトコル語彙としての批准は Sol 復帰後。

## 実施内容

- `mdex/context.py` に `zero_hits_field()` を追加し、`select_context` の「検索した上で候補 0 件」の出口で `zero_hits` を payload に付与。blank query と budget による全 drop は「検索した上での 0 件」ではないため主張しない (cdex の truncation accounting 区別と同一原則)。
- `mdex/multiindex.py`: マージ後 nodes が空かつ配下 context が zero_hits を主張しているとき、トップレベルにも `zero_hits` を付与。index DB 欠落のみのケースは別状態として主張しない。
- `mdex/cli.py` `find`: stdout の生配列契約 (空配列でも成功) を維持したまま、0 件時に stderr へ `{"zero_hits": ...}` を 1 行出力 (exit 0)。エラー契約 (stderr JSON + exit != 0) とは exit code と key で判別可能。
- `schemas/context.schema.json` に `zeroHits` 定義を追加。README の Output Contract に開示小節と find 行の注記、`docs/agent_integration.md` に「Zero Hits Are Not Absence」節と recovery loop を追加。

## 結果

- `find` 0 件: stdout `[]` + stderr に共通語彙の開示 (remediation は `rg -n "<terms>" .` / `cdex search` / frontmatter tags 追加を案内)。
- `context` 0 件: payload key `zero_hits` (schema-backed)。multi-index 経路も同様。
- ヒット時・blank query 時は主張しないことをテストで固定。テストスイート 402 件 pass (README 契約表と schema の整合テスト含む)。

- 2026-07-10 に Sol が条件付き批准 (`decision/zero-hit-disclosure-conditional-ratification.md`)。補正 (multi-index 誤主張の blocker 修正、table 0 件の明文化、remediation の cdex 任意ヒント化、`lanes_inactive` 常在 map 契約、0.5.0 bump) は同日適用済み。
