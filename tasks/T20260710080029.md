# Task: Adopt zero-hit disclosure for find and context

2026-07-10 の cdex Intake 評価 (cdex decisions/0003) で、エージェントが `mdex find` / `mdex context` の 0 件を「存在しない」と解釈する事故が確認された。0 件がメタデータレーンの範囲しか束縛しないことを payload で自己申告する。field 名 (`lanes_searched` / `lanes_inactive` / `caveat` / `remediation`) は cdex `zero_hits` (cdex `51c9ffa`) と共通語彙。mdex `70f9e24` で Sol の条件付き批准を反映して発効し、cdex 側も `676a0eb` で共通 shape への整合を実装した。

## 実施内容

- `mdex/context.py` に `zero_hits_field()` を追加し、`select_context` の「検索した上で候補 0 件」の出口で `zero_hits` を payload に付与。blank query と budget による全 drop は「検索した上での 0 件」ではないため主張しない (cdex の truncation accounting 区別と同一原則)。
- `mdex/multiindex.py`: 要求した全 index が実在して検索され、全配下 context が true zero を主張し、マージ後 nodes も空のときだけトップレベルに `zero_hits` を付与。hit 後の budget 全 drop や index DB 欠落は別状態として主張しない。
- `mdex/cli.py` `find`: stdout の既存契約 (JSON は空配列、table は空出力でも成功) を維持したまま、検索済み 0 件時に stderr へ `{"zero_hits": ...}` を 1 行出力 (exit 0)。エラー契約 (stderr JSON + exit != 0) とは exit code と key で判別可能。
- `schemas/context.schema.json` に `zeroHits` 定義を追加。README の Output Contract に開示小節と find 行の注記、`docs/agent_integration.md` に「Zero Hits Are Not Absence」節と recovery loop を追加。

## 結果

- `find` 0 件: stdout は JSON `[]` / table 空出力、stderr に共通語彙の開示。remediation は `rg` + frontmatter tags で自己完結し、`cdex search "<terms>"` は cdex が利用可能な場合だけの任意ヒント。
- `context` 0 件: payload key `zero_hits` (schema-backed)。multi-index は要求した全 index が検索済みかつ全 context が true zero の場合だけトップレベルで主張。
- ヒット時・blank query 時は主張しないことをテストで固定。文書 version 整合の回帰テスト追加後、テストスイートは 405 件 pass (README 契約表、schema 整合、table 0 件、multi-index 混在・欠落テストを含む)。
